    Making it real

    Hard to build alone. Easier with Red Hat.

    Most teams stall on the same four problems. Each one maps to something Red Hat already ships.

    Challenge

    Builds hide network calls

    Package managers fetch plugins, build tools and binaries on their own. Turn the network off and builds break in ways nobody documented.

    Trusted Software Supply Chain

    Pipelines built on the same Konflux and Hermeto tooling Red Hat uses for its own products. Prefetch is handled for common ecosystems, and undeclared fetches fail loudly instead of slipping through.

    Challenge

    Developers drift from the pipeline

    Code that builds on a laptop with open internet access breaks in the sealed build, so teams lose trust in the process.

    OpenShift Dev Spaces

    Workspaces defined in a devfile use the same base images and internal mirrors as the pipeline. Problems surface while coding, not at release time.

    Challenge

    Where do trusted inputs come from?

    Sealing the build only helps if what you prefetched was safe. Pinning a vulnerable package from a public registry just pins the risk.

    Red Hat Lightwell

    Lightwell Network supplies remediated, signed open source dependencies for Java and Python, with SBOMs, and backports fixes to the versions you already run. It becomes the trusted source your prefetch step pulls from.

    Challenge

    Proving it to auditors

    A sealed build is only half the value. The rest is evidence that holds up under review and policy that blocks anything unproven.

    Signer, Profile Analyzer, ACS

    Trusted Artifact Signer signs images and attestations. Trusted Profile Analyzer tracks SBOMs against new CVEs. Advanced Cluster Security keeps unsigned images off OpenShift.

    Red Hat builds its own products this way in Konflux, with Hermeto handling hermetic prefetch. Product names reflect Red Hat's trusted software supply chain portfolio; confirm current packaging with your product team.
